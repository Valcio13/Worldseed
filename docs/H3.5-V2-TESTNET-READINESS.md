# H3.5 — V2 Hemi Sepolia Readiness

Status: **not deployed; no public service is enabled.** This review covers the current local H2 candidate service and H3 Contract V2. Hemi Mainnet, production publishing, remote pushes, and V1 migration are out of scope.

## Review findings

### Confirmed behavior

- H2 uses Ethereum Sepolia (11155111), Hemi Sepolia (743111), and Bitcoin Testnet4. The EVM adapters check the provider chain IDs and canonical inclusion; confirmation thresholds are 12, 12, and 6 respectively. The BTC adapter excludes coinbase and rechecks the selected block hash. A source failure rejects the whole issuance. Selection is block-weighted, then transaction-uniform within that block; it is not uniform over all transactions in the window.
- The issuer derives three versioned seeds from transaction hashes and network IDs, derives the character seed from the ordered three source hashes, commits provenance, and signs the EIP-712 set for the configured V2 address. Solidity and viem agree on the digest, including the fixed `bytes32[3]` encoding; the V2 contract test checks this parity.
- D1 uses a unique `(player, expedition_number)` key. Refresh/interrupted-response retries return the persisted set. Expiry renewal reuses the same source records and seeds. The onchain contract checks expiry at `startExpedition`; an already-started run does not expire. A new test covers continuing an active run after the attestation window has elapsed.
- Owner and attester changes use two-step acceptance. Candidate signer rotation has no delay or onchain revocation list. Owner pause/unpause is immediate.
- Expedition inventory and starter grants are run-scoped. Abandonment consumes that run and its unfinished puzzle round; settled Gold and confirmed World Tree events remain. Region claims are per-run and the contribution nonce/ID plus one manual contribution per expedition prevent replay of the same event. The V2 test suite checks duplicate contribution rejection and persistence through abandonment.
- V2 and source generator version 2 use the same deterministic preview/gameplay generator. The preview tests check the same 49-cell output. The contract independently enforces action legality, region thresholds, and the completion predicate.
- Production deployed bytecode is **19,031 bytes**, below EIP-170's 24,576-byte limit. This is a local artifact size, not a deployment receipt or gas quote.
- Tracked files do not include `.env`, `.dev.vars`, key files, `node_modules`, or `dist`; ignore rules cover them. `.env.example` contains public addresses and empty secret placeholders. The tracked `.dev.vars.example` is an explicitly non-active template; its zero address is rejected by the endpoint. Do not copy it unchanged into an active signer service.

### Design trade-offs and unresolved blockers

- **The source attester is trusted.** The contract verifies its signature and records a source commitment; it cannot independently prove source-chain transaction existence, confirmations, or the adapter's random-selection fairness. Compromise or misconfiguration of the attester can issue false provenance. Use a dedicated signer, strict access, monitoring, and rotation procedure.
- **Selection lock has two meanings.** D1 durably locks the UI's chosen source. The EIP-712 signature covers all three seeds, and `startExpedition` locks one index onchain. The contract does not prove that the index matches D1's selected-source record; the authenticated wallet can submit any one of the three attested options. This still prevents introducing an unattested seed or changing the selected seed after the expedition starts.
- **Pause blocks economic and progress operations**, including expedition start, save, finish, shop purchases, World Tree contributions, and puzzle settlement. Abandonment is allowed as a safe exit: it clears the active run and forfeits unsettled puzzle state without granting resources or rewards. Starting/progressing another run remains blocked until the owner unpauses.
- **Abandoned-run community points remain.** Region unlocks and completion/explicit contributions already confirmed onchain are retained. Per-event replay protection stops reusing an event; it does not prevent a player from earning valid event points across multiple sequential runs. This preserves legitimate confirmed contributions as requested, but community-point policy should explicitly accept the resulting replay-across-runs economics.
- **Public source RPCs are a reliability dependency.** Defaults are public providers with no SLA. Timeouts/rate limits fail issuance with retryable responses. Configure independently operated testnet endpoints before a player test. Errors avoid printing signer keys; review server logs and provider URL handling before any production operation.
- **No active service can be configured yet.** V2 is undeployed and `wrangler.toml` has no real D1 ID. The migration directory is now explicitly configured as `db/migrations`. Unit tests use mocked D1 and source responses; they are not equivalent to a local Pages/D1/contract end-to-end run.
- **Local Wrangler environment isolation is mandatory.** Cloudflare's local Pages runtime imports `.env` values into the Worker by default. The first local startup showed the ignored project `.env` names for deployment/private-key variables in the Worker binding list (values were hidden); I stopped it before making any requests. No values were printed, transmitted, or published. Subsequent local checks used `CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV=false`, and the Worker then received only the configured D1 and Pages metadata bindings. Keep this setting for local Pages runs unless using a separate, disposable `.dev.vars` file. See [Cloudflare's local environment-variable guidance](https://developers.cloudflare.com/workers/local-development/environment-variables/).
- **No browser-wallet transaction test has occurred.** The open browser is showing the guest island on Vite port 5173; port 5174 currently fails to load. This does not exercise H2 Functions, V2, or a connected wallet.

No confirmed critical Solidity defect was found in the reviewed flows. The tests cover signature tampering/replay, sequential runs, abandonment accounting, region/World Tree accounting, completion, puzzle settlement/duplicate settlement, expiry, pause recovery, signer permissions/rotation, and insufficient-Gold shop rejection. The chief unresolved risks are service integration, signer trust, deployment configuration, and live provider behavior. A successful Gold-funded shop purchase still needs an end-to-end test.

## Exact deployment checklist (Hemi Sepolia only)

### Wallet roles and prerequisites

1. Select a **dedicated deployment wallet** funded with enough Hemi Sepolia ETH for the deployment transaction plus a reserve. Do not use a player wallet. The Hemi Sepolia deployment RPC must report chain ID `743111`.
2. Select an **attester wallet** dedicated to signing candidate sets. Its address must be set at deployment and the corresponding private key stored only as the Pages secret `WORLDSEED_ATTESTATION_PRIVATE_KEY`. Prefer separate custody from the owner/deployer. No key is needed in the browser.
3. Select the **owner address**. It controls pause, owner transfer, and attester proposals. A hardware wallet or multisig is preferable operationally, though the present contract has no timelock.
4. Obtain dedicated/test RPC URLs for Ethereum Sepolia and Hemi Sepolia and a reachable Bitcoin Testnet4 API endpoint. Confirm the source adapters can retrieve the required confirmations before opening issuance.
5. Public deployment is gated on explicit approval. Do not run these deployment or publishing steps as part of this review.

### Environment variables

**Local Hardhat deployment shell** (`.env`, ignored by Git):

```dotenv
HEMI_SEPOLIA_RPC_URL=<Hemi Sepolia JSON-RPC URL; chain ID must be 743111>
HEMI_SEPOLIA_PRIVATE_KEY=<funded disposable testnet deployer key>
HEMI_V2_OWNER_ADDRESS=<owner wallet address>
WORLDSEED_ATTESTER_ADDRESS=<candidate attester wallet address>
```

**Cloudflare Pages Functions server-side settings** (never `VITE_`):

```text
ETHEREUM_SEPOLIA_RPC_URL=<Ethereum Sepolia JSON-RPC URL; chain ID 11155111>
HEMI_SEPOLIA_RPC_URL=<Hemi Sepolia JSON-RPC URL; chain ID 743111>
BITCOIN_TESTNET4_API_URL=<Bitcoin Testnet4 API base URL>
WORLDSEED_V2_CONTRACT_ADDRESS=<actual deployed, nonzero V2 contract address>
WORLDSEED_ATTESTATION_PRIVATE_KEY=<attester key matching the contract's current attester>
WORLDSEED_V2_ATTESTER_ADDRESS=<public address of the contract's current attester>
```

Store `WORLDSEED_ATTESTATION_PRIVATE_KEY` using Cloudflare's secret binding, not a plain Pages variable. The function compares its derived signer address to `WORLDSEED_V2_ATTESTER_ADDRESS` and refuses issuance on mismatch. Set that public value from an onchain `attester()` read after deployment or rotation. A missing/zero V2 address must leave issuance disabled; never activate the function with a fabricated contract address.

**Public Pages build variable:**

```text
VITE_WORLDSEED_V2_CONTRACT_ADDRESS=<actual deployed V2 address>
```

`VITE_WORLDSEED_CONTRACT_ADDRESS` is the separate V1 reference address and must not be set to V2. No deployer, owner, or attester private key belongs in any `VITE_` variable.

### Ordered deployment procedure

1. Review the exact source revision and run `npm test`, `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`, `npm run contract:compile`, and `npm run contract:test`.
2. Set the four deployment-shell variables above in a local ignored `.env`. Never print the file, pass key values on a command line, or include them in logs. Check the RPC chain ID independently; the script also refuses any value other than 743111.
3. Estimate deployment gas against Hemi Sepolia and verify the funded deployer balance has a comfortable reserve. Current action estimates below are **local EVM estimates only**; no reliable Hemi deployment gas or fee can be stated until the network is queried.
4. With separate explicit approval, run `npm run contract:deploy:v2:testnet`. Record address, transaction hash, block number, receipt status, and `gasUsed`; confirm runtime bytecode equals the newly compiled artifact and confirm owner/attester addresses from chain reads.
5. Verify the source through an officially supported explorer route (Sourcify or explorer UI/API). This repository does not currently configure a Hardhat verification plugin, so do not assume `hardhat verify` is available. Record the actual verification result; matching bytecode alone is not public source verification.
6. Create a dedicated Cloudflare D1 database: `npx wrangler d1 create worldseed-h2`. Replace `database_id` in `wrangler.toml` with the returned real ID. The D1 binding name is `WORLDSEED_DB`, and migrations are under `db/migrations`.
7. Apply and verify the migration against the intended **test** database: `npx wrangler d1 migrations apply worldseed-h2 --remote`. Never point this command at an unrelated or production database.
8. Configure Pages Functions binding `WORLDSEED_DB` to that database. Add the source RPC/API URLs as server-side variables and the signer as a secret. Set the actual V2 address only after deployment. Configure the Pages build with `npm run build`, output `dist`, and public V2 address above. This checklist does not publish Pages.
9. Set `WORLDSEED_V2_ATTESTER_ADDRESS` from the contract's current onchain `attester()` read. The service rejects candidate issuance if the signing secret does not derive to that address. Deploy the Pages Functions only after separate approval, then test challenge, issuance, D1 retry, expiry renewal, selection, and the full connected-wallet flow with a disposable funded Hemi Sepolia wallet. Capture transaction hashes and receipts; verify state by reads after reload.

### Rotation and rollback

- **Signer rotation:** add the new signer as a server secret first; call `proposeAttester(newAddress)` from the owner, then `acceptAttester()` from the new signer. Confirm the onchain attester read before switching issuance to the new key. Revoke/delete the old secret after a verified test signature succeeds. The function must fail closed if its signer does not match the onchain attester.
- **Owner rotation:** call `transferOwnership(newOwner)` from the current owner, then `acceptOwnership()` from the new owner. Confirm onchain state before retiring the old key.
- **Rollback:** stop candidate issuance by disabling/reverting the Pages Function deployment and remove the attester secret from the active deployment. Unset the V2 frontend address and rebuild the frontend into an explicitly chosen safe mode; do not silently point V2 UI at V1. If contract state is unsafe, owner pause is an emergency stop; users can still abandon active runs, while other state-changing actions remain blocked. A new deployment is a fresh state; there is no proxy upgrade or V1 migration. Existing V2 expeditions and balances cannot be copied by this procedure. Preserve logs and transaction hashes for investigation.

Build with `VITE_WORLDSEED_V2_CONTRACT_ADDRESS` set to the local contract and run Pages dev with the D1 binding and `.env` loading disabled: `$env:CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV='false'; npx wrangler pages dev dist --port 8788`. The wallet must use a local chain configuration that is explicitly enabled for the test; do not change the production chain setting just to make a local test pass.
5. Test wallet request, candidate persistence, preview parity, selection, contract start, save/reload, rewards, puzzle settlement, Gold, World Tree, abandonment, next run, and rejected/reverted transactions.
