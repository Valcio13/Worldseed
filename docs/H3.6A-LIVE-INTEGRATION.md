## Candidate service and local contract result

Wrangler local D1 migrations and a local Pages Functions worker were exercised with genuine source adapters. Candidate challenge and candidate issuance worked, but the end-to-end contract start exposed a **signer configuration mismatch**: the candidate signature recovered to a different address from the attester configured on the disposable local V2 contract, and `startExpedition` reverted with `InvalidSignature`.

The repository already contained a `.dev.vars` file. Its contents were not read, changed, or printed. Because Wrangler's effective local signer did not match the isolated test contract, the complete local selection/start/abandon/next-expedition flow could not be safely completed. The local contract and Pages processes were stopped; temporary test files were removed. This is a deployment blocker, not evidence of a Solidity signature-encoding defect: a unit test also compares the contract digest with viem, but only a matching-key local end-to-end transaction will close this check.

The candidate endpoint now requires `WORLDSEED_V2_ATTESTER_ADDRESS` and compares it with the address derived from `WORLDSEED_ATTESTATION_PRIVATE_KEY`. On mismatch it returns HTTP 503 before returning or renewing a candidate set. Set the public attester-address variable from an onchain `attester()` read, and the secret from that same key. This guards configuration consistency; the deployment checklist must still independently confirm the onchain address after deployment or rotation.

The V2 deployment script also now refuses identical owner and attester addresses. The contract still trusts its owner to propose signer rotation, so separate custody remains an operational control rather than an onchain multisig/timelock guarantee.

The earlier local Pages check exercised the D1-backed challenge endpoint. A matching-key full-stack run is still needed to verify repeat/concurrent idempotency, expiry renewal, selection lock, EIP-712 recovery, contract start, abandonment, and a second expedition together. Browser-wallet and Cloudflare account tests remain outstanding.

## Emergency pause

`abandonExpedition` is now the sole state-changing exception to pause. It closes and forfeits the active run and unfinished puzzle, but it grants no inventory, Gold, region reward, or World Tree contribution. All starts and progress/economic actions remain paused, so abandonment cannot bypass the emergency stop. Contract regression tests verify owner-only pause control, allowed abandonment, unchanged weekly contribution totals, and blocked new starts until unpause.
